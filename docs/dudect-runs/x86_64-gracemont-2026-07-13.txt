Environment
-----------
  CPU:        Intel N100 (Gracemont E-cores)
  Compiler:   gcc (toolchain default)
  Target:     dudect (ichor_dudect_core built with NO hardware
              acceleration flags; ICHOR_AES_NI / ARMV8_AES / CLMUL /
              PMULL all disabled so the binary exercises the bitsliced
              src/aes_ct64.c path and the scalar carry-less multiply).

  Why this host: Gracemont is an in-order-ish Atom microarchitecture, a
  deliberately different x86_64 uarch from the Sandy Bridge-EP host.  Its
  integer-divide latency is data-dependent, so it is the strictest x86
  host for catching a divide- or shift-latency leak.

  cmake --build build --target dudect

Run 1 -- 2026-07-13  --all --samples 200000  (v1.0.0 software
                                              constant-time gate)
================================================================

  Full target set: the two harness sentinels, the four bitsliced-AES
  targets (key- and plaintext-varying, single and x4), the two scalar
  carry-less multiply targets, and the const_memcmp comparator added
  for the voleith 1.10.1 parity gate.

  sentinel_leak            |t| = 53479.55  FAIL  (expected sanity check)
  sentinel_clean           |t| =     0.32  PASS
  aes_ct64_encrypt_key     |t| =     0.05  PASS
  aes_ct64_encrypt_x4_key  |t| =     0.01  PASS
  aes_ct64_encrypt_pt      |t| =     0.26  PASS
  aes_ct64_encrypt_x4_pt   |t| =     0.01  PASS
  clmul64_scalar_b         |t| =     0.13  PASS
  clmul64_scalar_a         |t| =     0.13  PASS
  const_memcmp             |t| =     0.04  PASS  (new; parity gate)

  Notes:
    Clean run: the planted sentinel_leak fails (53479) and all eight real
    targets pass with the widest margin of the three hosts (max real
    |t| = 0.26, aes_ct64 plaintext path).  The data-dependent divide
    latency that makes Gracemont the strictest x86 host produces no
    signal here, since none of these paths use a secret-operand divide.

    const_memcmp: class A compares equal 32-byte buffers, class B buffers
    that differ in one byte at a uniformly random position; the fixed
    length and the OR-accumulator (no early exit) make the running time
    independent of both equality and first-difference position.

    SHAKE / Keccak is not dudected: it is constant-time by construction
    (no S-box, no data table, no secret-indexed load, no secret-dependent
    branch), so there is no timing signal for the harness to detect.

Run 2 -- 2026-07-14  --all --samples 200000  (Grøstl core-primitive
                                              gate, voleith 1.10.1)
================================================================

  Grøstl-256 and Grøstl-512 one-shot targets, added when the Grøstl
  core primitive moved into ichor for the libtalos_syndrome
  designated-opener driver.  Class A hashes an all-zero 256-byte
  message; class B a uniformly random 256-byte message; the length is
  fixed across both classes, so a PASS certifies the digest time is
  independent of message content (the bitsliced SubBytes path has no
  secret-indexed table load).

  grostl256_input          |t| = 0.02  PASS
  grostl512_input          |t| = 0.07  PASS

  Notes:
    The strictest x86 host produces the widest Grøstl margin of the
    three (max real |t| = 0.07, grostl512); the data-dependent divide
    latency that makes Gracemont strict finds no signal, since the
    Grøstl permutation uses no secret-operand divide.
